# Benchmark: OWASP

## Purpose

Use OWASP projects as practical technical references for web, API, and mobile application security. Select a version and verification depth appropriate to the system; OWASP Top 10 awareness materials are not, by themselves, a complete security assessment or assurance standard.

## Hospitality assessment topics

For web applications, APIs, mobile apps, and integrations, consider:

- Authentication, authorization, session management, and account recovery.
- Input handling, injection prevention, cryptography, and secure configuration.
- API inventory, object- and function-level authorization, rate limiting, and error handling.
- Dependency and software-supply-chain management, secrets handling, and secure release practices.
- Logging, privacy-preserving telemetry, abuse prevention, and security testing.
- Payment and identity integrations, channel-manager connections, and third-party webhooks.

Use OWASP ASVS as a testable verification reference where suitable, and relevant OWASP API Security and Mobile Application Security guidance for those components. Agree on safe, explicitly authorized testing boundaries before any validation.

## Evidence examples

Threat models, architecture diagrams, secure-development standards, dependency records, code-review controls, test results, API inventories, remediation records, and release approvals.

## Assessment caveat

Record the OWASP project, edition/version, scope, and selected requirements. Do not imply that a system is “OWASP certified.” No live testing is authorized by this benchmark document.
